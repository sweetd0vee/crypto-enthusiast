# Требования к сервису

## Назначение

Сервис проводит анонимный опрос во время минутного телевизионного ролика.
Зритель открывает ссылку из QR-кода и выбирает один вариант без регистрации.
Администратор создаёт вопросы и видит только обезличенные суммы.

Расчётный верхний ориентир — 100 млн зрителей за 60 секунд. Локальная версия
не имитирует такой объём, но сохраняет нужную семантику и архитектурные
границы горячего пути.

## Роли

### Зритель

- открывает `/questionnaire/{id}`;
- видит опубликованный вопрос только внутри его временного окна;
- отправляет один из 2–10 вариантов;
- с одного браузера голосует по вопросу один раз;
- не видит текущие результаты и служебные данные.

### Администратор

- создаёт и редактирует вопросы;
- публикует, отменяет и удаляет допустимые черновики;
- просматривает обезличенные результаты;
- вызывает принудительный пересчёт результата из журнала.

Административный API защищён Bearer-токеном. Локальное значение
`dev-admin-token` предназначено только для разработки.

## Модель вопроса

В ролике всегда один вопрос:

- `name` — текст;
- `options` — от 2 до 10 пар `{key, label}`;
- `show_time` — начало приёма голосов в UTC;
- `duration_seconds` — длительность от 10 до 3600 секунд;
- `status` — `draft`, `published` или `cancelled`.

Эффективный статус вычисляется по серверному времени:

- `draft` и `cancelled` совпадают с сохранённым статусом;
- опубликованный вопрос до `show_time` — `scheduled`;
- внутри `[show_time, show_time + duration)` — `live`;
- после конца полуоткрытого интервала — `closed`.

Отдельный cron для изменения статуса не используется.

## Правила голосования

Проверки выполняются в фиксированном порядке:

1. вопрос существует и опубликован;
2. серверное время находится внутри окна;
3. ключ варианта существует;
4. браузер ещё не голосовал;
5. дедупликация и увеличение счётчика выполняются атомарно.

Сервер выдаёт cookie `vid`. Дедупликация строится по хешу
`question_id + vid`; IP не входит в уникальность, поэтому разные люди за NAT
не склеиваются. Новый браузер, инкогнито и очистка cookie считаются допустимым
обходом базовой защиты.

Голос после конца окна не принимается, даже если форма была открыта заранее.
Два параллельных запроса с одним `vid` увеличивают результат ровно один раз.

## Правила изменения данных

- варианты вопроса с голосами менять нельзя;
- удалить можно только черновик без голосов;
- опубликованный вопрос снимается с эфира статусом `cancelled`;
- изменение текста не меняет накопленные счётчики;
- результат содержит все варианты, включая варианты с нулём голосов;
- `total` всегда равен сумме `count`.

## Приватность

- регистрация и профиль зрителя отсутствуют;
- сырой IP не хранится и не возвращается;
- в журнале находятся только хеш cookie, хеш IP, вариант и серверное время;
- публичного списка голосов нет;
- API результатов не содержит cookie, IP или их хеши.

## Поведение при отказах

- без Redis голосование останавливается с `503`, чтобы не нарушить дедуп;
- PostgreSQL остаётся источником вопросов и журналом для пересчёта;
- Redis хранит оперативный кэш, дедупликацию и счётчики;
- закрытый результат можно восстановить из журнала;
- административный CRUD не используется на горячем пути каждого голоса.

Текущие ограничения и целевое масштабирование описаны в
[архитектуре](02-architecture.md), HTTP-контракт — в [API](05-api.md).

## Критерии приёмки

1. Создание опубликованного вопроса с динамическими вариантами.
2. До начала возвращается `window_not_started`.
3. В окне публичный ответ содержит только вопрос, варианты и `closes_at`.
4. Первый голос возвращает `201`, повтор того же браузера — `409`.
5. Второй браузер с того же IP учитывается отдельно.
6. Несуществующий вариант возвращает `422`.
7. После окна возвращается `410`, счётчики не меняются.
8. Результат сходится по вариантам и не содержит идентификаторов зрителя.
9. Редактирование и удаление черновика работают; защищённые операции дают
   конфликт.
10. `make verify` проходит backend, frontend, Docker, HTTP и browser-сценарии.

## Вне текущего скоупа

- регистрация зрителей и защита от профессиональных ботов;
- несколько вопросов в одном ролике;
- мультитенантность, биллинг и полнотекстовый поиск;
- публичные live-результаты;
- production IAM, multi-region и Kubernetes-манифесты.

Оставшиеся production-задачи перечислены в
[roadmap](08-production-roadmap.md).
