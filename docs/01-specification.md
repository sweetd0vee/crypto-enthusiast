# Требования

Сервис проводит один анонимный вопрос во время минутного телеролика.
Зритель открывает ссылку из QR и выбирает вариант без регистрации.
Администратор создаёт вопросы и видит только обезличенные суммы.

Расчётный верхний ориентир — 100 млн зрителей за 60 секунд. Локальная
версия этот объём не имитирует, но сохраняет семантику горячего пути.
Как код проводит пик, описано в [нагрузке](08-load.md).

## Роли

Зритель открывает `/questionnaire/{id}`, видит опубликованный вопрос только
внутри его окна, отправляет один из 2–10 вариантов и с одного браузера
голосует по вопросу один раз. Текущие суммы и служебные поля ему не
отдаются.

Администратор создаёт и редактирует вопросы, публикует и отменяет их,
удаляет допустимый черновик, смотрит суммы и может пересчитать результат
из журнала. Административный API закрыт заголовком
`Authorization: Bearer <токен>`. Локальное значение `dev-admin-token`
предназначено только для разработки.

## Вопрос

В ролике один вопрос:

- `name` — текст;
- `options` — от 2 до 10 пар `{key, label}`, ключи уникальны;
- `show_time` — начало приёма голосов, UTC, обязательно для `published`;
- `duration_seconds` — от 10 до 3600, по умолчанию 60;
- сохранённый `status` — `draft`, `published` или `cancelled`.

`scheduled`, `live` и `closed` в базу не пишутся. Их считает сервер:

- `draft` и `cancelled` остаются как сохранены;
- опубликованный вопрос до `show_time` — `scheduled`;
- внутри `[show_time, show_time + duration)` — `live`;
- с момента закрытия и дальше — `closed`.

Отдельного cron для смены статуса нет. Часы телефона зрителя не используются.

## Голосование

Проверки идут в одном порядке:

1. вопрос существует и опубликован;
2. серверное время внутри окна;
3. ключ варианта существует;
4. этот браузер ещё не голосовал;
5. отметка дедупликации и увеличение счётчика выполняются одной операцией Redis.

Сервер выдаёт cookie `vid`. Уникальность голоса — хеш `question_id` и `vid`.
IP в уникальность не входит: люди за одним NAT не склеиваются. Инкогнито,
другой браузер и очистка cookie обходят защиту. Это базовая дедупликация
для обычного зрителя, не защита от бота.

Голос после конца окна не принимается, даже если форма была открыта заранее.
Два параллельных запроса с одним `vid` увеличивают результат ровно один раз.

## Изменение данных

- варианты вопроса, по которому уже есть голоса, менять нельзя;
- удалить можно только черновик без голосов;
- опубликованный вопрос снимают статусом `cancelled`, а не удалением;
- правка текста не обнуляет счётчики;
- в результате есть все варианты, включая нулевые;
- `total` равен сумме `count`.

## Приватность

Регистрации нет. Сырой IP не хранится и не возвращается. В журнале лежат
хеш cookie, хеш IP, вариант и серверное время. Публичного списка голосов
нет. Ответ с результатами не содержит cookie, IP и хешей.

## Отказы

Если Redis недоступен, голосование отвечает `503`. Запасная запись каждого
голоса сразу в PostgreSQL запрещена: общий дедуп разъедется. PostgreSQL
хранит вопросы и журнал для пересчёта. Закрытый результат можно восстановить
из журнала. Пока вопрос `live`, автоматический пересчёт журнала не запускается.

## Приёмка

1. Создание опубликованного вопроса с динамическими вариантами.
2. До начала — `window_not_started`.
3. В окне публичный ответ содержит только вопрос, варианты и `closes_at`.
4. Первый голос — `201`, повтор того же браузера — `409`.
5. Второй браузер с того же IP учитывается отдельно.
6. Несуществующий вариант — `422`, счётчик не меняется.
7. После окна — `410`, счётчики не меняются.
8. Результат сходится по вариантам и не содержит идентификаторов зрителя.
9. Черновик можно изменить и удалить; защищённые операции дают `409`.
10. `make verify` проходит backend, frontend, Docker, HTTP и браузер.

## Вне скоупа

Регистрация зрителей, защита от ботов, несколько вопросов в одном ролике,
мультитенантность, биллинг, поиск, публичные live-результаты, production IAM,
multi-region и Kubernetes. Оставшиеся production-дыры перечислены в
[roadmap](05-production-roadmap.md).
