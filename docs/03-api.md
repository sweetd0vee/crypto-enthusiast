# API

HTTP API сервиса минутного ТВ-опроса. Зритель открывает форму и отдаёт один голос без регистрации. Администратор создаёт вопросы и смотрит обезличенные суммы.

Интерактивная схема — `GET /docs`, машинная — `GET /openapi.json`. Готовая коллекция запросов — в [`postman/`](../postman/).

## Общие правила

| | |
| --- | --- |
| Прямой адрес API | `http://localhost:8080` |
| Тот же origin, что и интерфейс | `http://localhost:3000` — Nginx проксирует `/questionnaire`, `/questions`, `/healthz`, `/docs`, `/openapi.json` |
| Тело | `Content-Type: application/json` |
| Время | ISO-8601 с часовым поясом. Сервер хранит и отдаёт UTC |
| Идентификатор вопроса | целое число в пути |

Ошибка всегда одного вида. Поле `error` стабильно для клиента, `message` можно показать человеку:

```json
{"error": "window_closed", "message": "Время голосования истекло"}
```

Некорректный JSON, пустые обязательные поля и неверный тип в пути дают `422` с `error: "invalid_body"`.

### Авторизация

Публичные маршруты (`/questionnaire/...`, `/healthz`) токена не требуют.

Админские маршруты (`/questions...`) требуют заголовок:

```http
Authorization: Bearer dev-admin-token
```

Локальное значение задаётся `ADMIN_TOKEN`. Нет заголовка или токен не совпал — `401 unauthorized`.

### Cookie зрителя

Сервер выдаёт cookie `vid` — UUID. Она нужна, чтобы один браузер ответил по вопросу один раз.

| Атрибут | Значение |
| --- | --- |
| Имя | `vid` |
| `HttpOnly` | да |
| `SameSite` | `Lax` |
| `Path` | `/` |
| `Max-Age` | 86400 секунд (сутки) |

Cookie ставится заголовком `Set-Cookie`, если её не было или значение не UUID. Клиент присылает её обратно обычным `Cookie`. Дедупликация считается по хешу `question_id` и `vid`. IP в уникальность не входит и в ответах не появляется.

## Служебный маршрут

### `GET /healthz`

Проверка, что процесс API достучался до PostgreSQL и Redis. Токен не нужен.

Успех `200`:

```json
{"status": "ok"}
```

Если хранилище не отвечает — `503`:

```json
{"error": "unavailable", "message": "Хранилище недоступно"}
```

Отдельно Nginx на порту интерфейса отвечает на `GET /health` текстом `ok`. Это проверка самого Nginx, не API.

## Зритель

Оба маршрута читают карточку вопроса из Redis. Если карточки там нет, берут её из PostgreSQL и кладут в кэш. Голосовать можно только у опубликованного вопроса и только пока серверное время внутри полуоткрытого окна `[show_time, show_time + duration_seconds)`.

Проверки идут в одном порядке:

1. вопрос существует;
2. статус `published`;
3. окно уже началось и ещё не кончилось;
4. у `POST` — ключ варианта есть в вопросе;
5. этот `vid` ещё не голосовал.

### `GET /questionnaire/{question_id}`

Форма для страницы по QR. Текущие суммы не отдаются.

Успех `200`. Если cookie не было, в ответе есть `Set-Cookie`:

```json
{
  "id": 1,
  "name": "Какой привод практичнее?",
  "closes_at": "2026-09-24T18:01:00Z",
  "options": [
    {"key": "a", "label": "Передний"},
    {"key": "b", "label": "Задний"},
    {"key": "c", "label": "Полный"},
    {"key": "d", "label": "Подключаемый"}
  ]
}
```

`closes_at` — момент, когда окно закроется. Вариант с нулём голосов здесь не отличается от остальных: счётчиков в этом ответе нет.

| Код | `error` | Когда |
| --- | --- | --- |
| 404 | `not_found` | вопроса нет |
| 403 | `not_published` | `draft` или `cancelled` |
| 403 | `window_not_started` | серверное время меньше `show_time` |
| 410 | `window_closed` | серверное время больше или равно концу окна |
| 409 | `already_voted` | этот `vid` уже ответил |
| 503 | `unavailable` | Redis не отвечает |

```bash
curl -sS -c /tmp/vid.txt -b /tmp/vid.txt \
  http://localhost:8080/questionnaire/1
```

### `POST /questionnaire/{question_id}/votes`

Принять один голос.

```json
{"option": "a"}
```

`option` — ключ варианта, от 1 до 64 символов.

Успех `201`:

```json
{"status": "accepted", "question_id": 1, "option": "a"}
```

Отметка «уже голосовал» и увеличение счётчика делаются одним скриптом Redis. Повтор с тем же `vid` получает `409` и счётчик не меняет. Ответ уходит после успешного обновления Redis. Строка журнала пишется отдельно и в это тело не попадает.

Ошибки те же, что у получения формы, плюс:

| Код | `error` | Когда |
| --- | --- | --- |
| 422 | `invalid_option` | такого ключа нет среди вариантов |
| 422 | `invalid_body` | нет поля `option`, пустая строка или не JSON |
| 503 | `unavailable` | Redis не отвечает, голос не принят |

```bash
curl -sS -c /tmp/vid.txt -b /tmp/vid.txt \
  -H 'content-type: application/json' \
  -d '{"option":"a"}' \
  http://localhost:8080/questionnaire/1/votes
```

Повтор той же пары команд с тем же файлом cookie даёт `409`.

## Админ: вопросы

Все маршруты ниже требуют `Authorization: Bearer <токен>`. Без него — `401`.

Карточка вопроса в ответах одна и та же:

```json
{
  "id": 1,
  "name": "Какой привод практичнее?",
  "status": "published",
  "effective_status": "scheduled",
  "show_time": "2026-09-24T18:00:00Z",
  "duration_seconds": 60,
  "options": [
    {"key": "a", "label": "Передний", "position": 0},
    {"key": "b", "label": "Задний", "position": 1},
    {"key": "c", "label": "Полный", "position": 2},
    {"key": "d", "label": "Подключаемый", "position": 3}
  ]
}
```

`status` — то, что сохранил админ: `draft`, `published`, `cancelled`. `effective_status` считается в момент запроса и в базе отдельно не лежит:

| `effective_status` | Условие |
| --- | --- |
| `draft` | сохранённый статус `draft` |
| `cancelled` | сохранённый статус `cancelled` |
| `scheduled` | опубликован, но `now` меньше `show_time` |
| `live` | опубликован и `now` внутри окна |
| `closed` | опубликован и окно уже кончилось |

Тело создания и изменения:

| Поле | Правило |
| --- | --- |
| `name` | непустая строка, пробелы по краям срезаются |
| `status` | при создании `draft` или `published`, по умолчанию `draft`; при изменении ещё и `cancelled` |
| `show_time` | ISO-8601 с часовым поясом. Обязателен, если статус `published` |
| `duration_seconds` | целое от 10 до 3600, по умолчанию 60 |
| `options` | от 2 до 10 элементов |
| `options[].key` | 1–64 символа, ключи внутри вопроса уникальны |
| `options[].label` | непустая строка |

Нарушение этих правил — `422 invalid_body`.

### `POST /questions`

Создать вопрос. Успех `201` — карточка. A/B — тот же метод, в `options` два элемента.

```json
{
  "name": "Какой привод практичнее?",
  "show_time": "2026-09-24T18:00:00Z",
  "duration_seconds": 60,
  "status": "published",
  "options": [
    {"key": "a", "label": "Передний"},
    {"key": "b", "label": "Задний"},
    {"key": "c", "label": "Полный"},
    {"key": "d", "label": "Подключаемый"}
  ]
}
```

Для локальной проверки `show_time` ставят на несколько секунд вперёд или увеличивают `duration_seconds`.

### `GET /questions`

Список всех вопросов. Успех `200` — массив карточек, по возрастанию `id`. Варианты внутри карточки идут по `position`. Пустая база — `[]`.

### `GET /questions/{question_id}`

Одна карточка. Успех `200`. Нет вопроса — `404 not_found`.

### `PUT /questions/{question_id}`

Полная замена полей. Тело то же, что у создания, но `status` может быть `cancelled`. Успех `200` — обновлённая карточка.

Если по вопросу уже есть голоса (в журнале или в счётчиках Redis) и набор вариантов изменился — ключ или подпись — ответ `409`:

```json
{"error": "options_locked", "message": "Нельзя менять варианты после появления голосов"}
```

Текст вопроса, время и статус при этом менять можно. Опубликованный вопрос снимают с эфира телом со `"status": "cancelled"`.

### `DELETE /questions/{question_id}`

Удалить вопрос.

- черновик без голосов — `204`, тела нет;
- статус не `draft` или голоса уже есть — `409 delete_forbidden`.

Опубликованный вопрос этим методом не снимают: его отменяют через `PUT`.

## Админ: результат

Итог — суммы по вариантам. Cookie, IP и хеши в ответ не входят. Вариант с нулём голосов всё равно есть в `counts`. `total` равен сумме `count`.

```json
{
  "question_id": 1,
  "name": "Какой привод практичнее?",
  "effective_status": "closed",
  "total": 9001500,
  "counts": [
    {"key": "a", "label": "Передний", "count": 600},
    {"key": "b", "label": "Задний", "count": 900},
    {"key": "c", "label": "Полный", "count": 9000000},
    {"key": "d", "label": "Подключаемый", "count": 8100}
  ]
}
```

Пока вопрос `live`, цифры читаются из шардов Redis. Если шардов нет и вопрос уже не в эфире, сервер один раз собирает суммы из журнала `vote`, пишет снимок и отдаёт его. Во время эфира пустые счётчики не пересчитываются из журнала: ответ будет с нулями.

Redis недоступен — `503 unavailable` с текстом «Счётчики временно недоступны». Нет вопроса — `404 not_found`.

### `GET /questions/{question_id}/results`

Текущий итог. Успех `200` — объект выше.

### `POST /questions/{question_id}/results/rebuild`

Пересчитать итог из таблицы `vote`, записать снимок в `question_result` и заменить счётчики Redis. Успех `200` — тот же объект, что у чтения. Тела запрос не требует.

## Коды ошибок

| Код | `error` | `message` | Когда |
| --- | --- | --- | --- |
| 401 | `unauthorized` | Нужен токен администратора | нет или неверный токен админа |
| 403 | `not_published` | Вопрос не опубликован | `draft` или `cancelled` на публичном маршруте |
| 403 | `window_not_started` | Голосование ещё не началось | `now` меньше `show_time` |
| 404 | `not_found` | Вопрос не найден | нет вопроса |
| 409 | `already_voted` | Вы уже проголосовали | этот `vid` уже ответил |
| 409 | `options_locked` | Нельзя менять варианты после появления голосов | другой набор `options` при уже существующих голосах |
| 409 | `delete_forbidden` | Можно удалить только черновик без голосов | удаление не-черновика или вопроса с голосами |
| 410 | `window_closed` | Время голосования истекло | `now` больше или равен концу окна |
| 422 | `invalid_option` | Такого варианта ответа нет | ключа нет среди вариантов |
| 422 | `invalid_body` | Некорректное тело запроса | битый JSON, пустое имя, меньше двух вариантов, неверный тип в пути |
| 503 | `unavailable` | Сервис голосования временно недоступен | Redis недоступен на публичном маршруте |
| 503 | `unavailable` | Счётчики временно недоступны | Redis недоступен при чтении или пересчёте итога |
| 503 | `unavailable` | Хранилище недоступно | PostgreSQL или Redis не отвечают на `/healthz` |
