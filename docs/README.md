# ТВ-опрос: суть решения

Национальная компания показывает минутный ролик на ТВ. В ролике один вопрос и QR. Зритель открывает ссылку и голосует без регистрации. Админ заранее создаёт опрос и смотрит обезличенные суммы, а не список людей.

Референс [Questionnaire-API](https://github.com/ayshajamjam/Questionnaire-API) — это другой продукт: банк вопросов для класса, правильный ответ, пользователи, рейтинг, Auth0. Из него берём только форму CRUD вопросов (`POST/PUT/GET/DELETE /questions`). Пользователей, лидерборд, «правильный ответ» и логин зрителя не переносим: задание прямо запрещает регистрацию и просит обезличенный итог.

## Идея в одном абзаце

Два контура. Админка редкая: вопрос и варианты лежат в PostgreSQL. Голосование длится около 60 секунд и может принести до ~100 млн ответов: запрос не пишет строку и не считает `GROUP BY` в базе. Он атомарно ставит отметку «этот браузер уже голосовал» в Redis, увеличивает счётчик варианта и только потом, пачкой, дописывает журнал голосов в PostgreSQL. Экран результатов читает счётчики. Таблица ответов нужна, чтобы пересчитать итог, если Redis пропал, а не чтобы рисовать дашборд.

Почему так: 100 млн голосов за 60 секунд — это около 1,7 млн запросов в секунду на один вопрос. `COUNT(*) GROUP BY` по 10 млн строк на каждое открытие админки этот поток не переживёт. Счётчик в момент голоса — O(1).

## Что сознательно не делаем

- Нет аккаунтов зрителей и нет «правильного» варианта. Это опрос, не экзамен.
- Дедупликация базовая: один голос на браузер (cookie). Обычный зритель не накрутит повторной отправкой формы. Инкогнито и второй телефон обходят защиту — по условию это допустимо.
- IP не является ключом уникальности. У мобильных операторов тысячи людей сидят за одним адресом (CGNAT). Уникальность по IP вычеркнет живых зрителей.
- Elasticsearch не нужен: искать по тексту голосов не требуется, нужны суммы по 2–N вариантам.
- Kubernetes в тестовом — целевая среда компании, локально достаточно Docker Compose.

## Стек

Python (FastAPI, горячий путь и админский CRUD), PostgreSQL (вопросы, журнал голосов, снимок итога), Redis (дедуп и счётчики), React (форма по QR и админка). Фреймворки и что сознательно не берём — в [стеке](06-stack.md).
