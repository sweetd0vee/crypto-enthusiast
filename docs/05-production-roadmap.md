# Что ещё не сделано

Локальный контур и проверки описаны в [стеке](04-stack.md). Здесь только
дыры текущей версии. Уже сделанное — атомарный Lua, запрет `GROUP BY` на
`live`, QR и SVG для `scheduled`/`live`, same-origin cookie, hash-партиции
журнала — сюда не входит.

## Журнал не переживает процесс

`VOTE_ASYNC=true` кладёт событие в `asyncio.Queue` на 10 000 элементов.
Полная очередь пишет в лог и теряет событие. Рестарт API теряет несброшенный
batch. Синхронная ошибка `INSERT` тоже не откатывает счётчик Redis: зрителю
уже ушёл `201`.

Нужны запись события в той же атомарной операции, что дедуп и `HINCRBY`,
consumer вне памяти API, подтверждение только после commit и сверка
`Redis ↔ vote ↔ question_result`. Пока этого нет, подтверждённый голос может
отсутствовать в журнале.

## Результат не финализируется сам

Автоматический rebuild закрытого вопроса без ключей Redis есть. Нет
состояний `finalizing` / `final`, срока хранения журнала и отдельного
удаления крупных эфиров. Hash-партиции по `question_id` не размазывают
запись одного ролика. Кнопки пересчёта в админке нет, только
`POST /questions/{id}/results/rebuild`.

## Безопасность локальная

Админ — один Bearer-токен из окружения, сравнение через `hmac.compare_digest`.
Отозвать доступ без деплоя нельзя. Cookie `vid` без флага `Secure`. Нет
ограничения тела, rate limit и проверки зависимостей сверх `npm audit` во
frontend job. IP по-прежнему не должен становиться ключом голоса.

## Наблюдаемости нет

Логи текстовые. Нет метрик RPS и latency, счётчиков принятых и повторных
голосов, глубины очереди журнала, трейсов и алертов.

## Админка без серверного списка

Фильтры, сортировка и номера строк считаются в браузере по полному
`GET /questions`. Нет постраничной выдачи, optimistic locking, аудита правок
и экспорта результата. Карточка вопроса в Redis без TTL: правка её
перезаписывает, а тихий сбой записи кэша сам не истекает.

## Нагрузка не подтверждена

`backend/scripts/load_test.py` — локальный дым, не capacity-тест. В именах
ключей нет hash tag, поэтому текущий `EVAL` на Redis Cluster не переносится
без смены ключей. Несколько реплик API возможны, потому что процесс ничего
не помнит, но балансировщик, отдельные пулы public/admin и запас ёмкости не
собраны.

Kubernetes, Kafka и multi-region не добавляются, пока нет измерения и
отдельного решения, как склеивать дедуп между регионами.
