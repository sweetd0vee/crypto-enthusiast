# План фронтенда

Фронт начинается после шагов 1–7 бэкенда: контракт уже стабильный, приёмка проходит curl-ами. В условии фронт необязателен. Если время есть, он сильнее всего показывает форму по QR и таблицу результатов — то, что ревьюер откроет руками.

Стек экранов: React 18, TypeScript, Vite, React Router. Запросы — `fetch`. Состояние сервера локальное в страницах. Состав зависимостей и что не подключаем — в [стеке](06-stack.md).

## Два независимых экрана

Один бандл, два маршрута. Зрительский экран не тащит админский токен.

| Маршрут | Кто | API |
| --- | --- | --- |
| `/q/:id` | зритель с телефона | `GET /questionnaire/{id}`, `POST /questionnaire/{id}/votes` |
| `/admin` | админ | CRUD `/questions`, `GET /questions/{id}/results` |

Прокси Vite на `localhost:8080`, чтобы cookie `vid` была same-site в локальной проверке. Cookie ставит бэкенд, фронт её не читает и не генерирует.

Токен админа: поле на `/admin/login`, значение в `sessionStorage`. Заголовок `Authorization` вешает тонкая обёртка над `fetch`. В репозиторий токен не записывать.

## Экран зрителя

Мобильная колонка, крупные кнопки: QR открывают с телефона у телевизора.

Состояния, каждое со своим текстом, без общей «Ошибка сервера»:

- загрузка;
- форма: текст вопроса и кнопки по `options`, подпись «можно ответить до {closes_at}» в локальной таймзоне;
- `window_not_started` — «Голосование ещё не началось»;
- `window_closed` — «Время ролика вышло»;
- `already_voted` — «Вы уже ответили»;
- `not_published` / `404` — «Ссылка недействительна»;
- успех после `201` — «Ответ принят», кнопки больше не активны;
- сеть — «Не удалось отправить, попробуйте ещё раз» (повтор безопасен: дедуп не даст второй голос).

Отправка: одна выбранная кнопка, повторный тап блокируется на клиенте, но сервер всё равно источник правды.

Проценты на этом экране не показываем.

## Админка

Страница `/admin` — таблица вопросов.

Колонки: id, имя, эффективный статус, `show_time`, длительность, действия.

Кнопки:

- «Создать» — форма: имя, datetime-local для `show_time`, длительность, статус, динамический список вариантов (добавить / убрать строку, ключ и подпись). Минимум две строки;
- «Изменить» — та же форма, `PUT`;
- «Удалить» — `DELETE`, для опубликованного с голосами показать текст ошибки `options_locked` / конфликт удаления;
- «Результаты» — переход на `/admin/questions/:id`.

Таблица на первом проходе без пагинации: вопросов в тестовом единицы. Позже — `limit/offset`, если список разрастётся. В API список сразу отдавать массивом.

### Результаты

`/admin/questions/:id` рисует полосы: подпись варианта, абсолютное число, доля от `total`.

Пока `effective_status = live`, страница раз в 2 секунды повторяет `GET /questions/{id}/results`. Это единственное «реальное время»: тянем готовые суммы, не поток сырых голосов. Когда статус `closed`, опрос прекращаем и оставляем снимок.

Пустой опрос: все нули и фраза «Пока нет ответов».

## Шаги

1. Vite-проект в `frontend/`, прокси на API, маршрут `/q/:id` с разбором кодов ошибок. Проверка: открыть вопрос в окне, проголосовать, обновить страницу, увидеть «уже ответили».
2. Форма создания и таблица на `/admin`. Проверка: создать вопрос, увидеть его в списке, удалить черновик.
3. Страница результатов и опрос раз в 2 секунды на живом окне. Проверка: отправить голос из второго браузера (или инкогнито) и увидеть, что число выросло без ручного обновления.
4. Короткая секция в корневом README: `cd frontend && npm install && npm run dev`, адрес зрителя и адрес админки.

## Что проверить руками

- ширина 390px: кнопки варианта на всю ширину, текст вопроса не обрезан;
- двойной клик по варианту не даёт двух голосов;
- админка без токена не показывает таблицу, а форму входа;
- после `window_closed` полосы остаются, новые голоса с `/q/:id` не увеличивают числа.

## Вне этого этапа

- графики, экспорт CSV, роли админов, тёмная тема;
- websocket. Интервала в 2 секунды по агрегату достаточно для минутного ролика и проще в сдаче.
